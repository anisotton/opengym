# Upstream openGym v1.4.2 Merge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring every upstream commit (DuarteSantos8/openGym, fork point `e88062ed0` = v1.3.9, tip `042c9ee42` = v1.4.2 + 3) into the Brilhart Fitness fork with the fork's customizations intact and both test suites green.

**Architecture:** Four true merges (`--no-ff`), one per upstream tag, in a dedicated worktree on branch `merge/upstream-v1.4.2`, based on `fix/upstream-security-v1.4.2` (whose ported security fixes are already the Postgres-shaped form of four upstream commits, so those conflicts resolve to ours). Every upstream `server.js` change that touches `db.*` / `saveDb()` / `readState`-on-disk is rewritten against `api/store.js` (PostgreSQL); every new upstream UI string that names the product goes through the same rebrand pass ISO-1385 did. Each tag merge ends with `npm run test:pg` (api) and `npm test` (frontend) green, modulo the one known pre-existing failure, and a merge commit.

**Tech Stack:** git (merge, rerere), Node 22, PostgreSQL (api suite via `api/scripts/test-with-pg.sh`), vitest.

**Spec:** this plan is its own spec; the decisions below were taken on 2026-10-25 with Anderson (see memory `brilhart-upstream-sync`).

## Global Constraints

- Branch out of `release/0.0.0-alpha` only; push only to `git@github.com:anisotton/opengym.git`; merge into release is the Oráculo's job after Sentinel review (never done here).
- API dependencies stay `@simplewebauthn/server`, `pg`, `stripe`, `undici`, `web-push`; frontend stays React + Router + Zustand (+ Capacitor). Upstream adds no new runtime deps; take their Capacitor 8 bumps as they come.
- `db.json` stays retired: no module-level `db`, no `saveDb()`. Upstream's `durable.js` may stay for Coach/media files only.
- Known pre-existing failure allowed: `prompt-split.test.js` "older sessions in a review window are compacted". Everything else must pass.
- Every upstream string naming the product ("openGym") becomes "Brilhart Fitness" in UI copy and locale keys (ISO-1385 rule); upstream's own name stays in NOTICE/licence/attribution text.
- Exercise media: Anderson decided on 2026-10-25 to do exactly as upstream (catalogue/media/ baked into the `web` image, served from /exercise-media/), taking the Gym visual licence risk (catalogue/media/NOTICE.md says the media is for the openGym application only, non-commercial forks). The old `media` compose service/profile and the `./media` bind mounts go away as upstream removed them. The licence position must be reviewed by the lawyer before the paid launch; NOTICE.md keeps upstream's text verbatim.
- Our routes that upstream lacks must survive untouched: billing/*, account/email/*, recover/*, account/terms/accept, client-event, admin/program*, `DELETE /api/account`, `/api/health` DB ping.

## Review Focus

1. A v1.3.9-era phone (no sync stamps) PUTting its state against our Postgres `putUserState` CAS: `stampPut` must run inside the `decide` callback, and `_wid`/`_wids` must be stored in `user_state.state` so `baseWid` refusal works. Test: port upstream `server-sync-stamps*.test.js` to `spawnApi`.
2. The reminder/nudge tick reading every profile via `getAllUsers`/`getUserState` once per 10 s with `queue.js`: must not regress to a query per user. Test: `server-reminder.test.js` + upstream's nudge tests ported.
3. `FIRST_USER_ADMIN=1` on an empty Postgres instance must make the first `createUser` an admin (users.admin column or `extra`), and the ISO-1449 "admin without training data" path must still hold. Test: port upstream's first-user-admin test.
4. Account deletion: upstream's `POST /api/account/delete` (owner's proof) vs ours `DELETE /api/account` (ISO-1447, Stripe cleanup outbox). Keep ours as the server contract; map upstream's `DeleteAccount.jsx` UI onto ours only where it adds (backup offer, typed name). Test: `server-account-delete.test.js` (ours) still green.
5. `web/Dockerfile`: upstream's non-root nginx (uid 101) + CSP env + BASE_PATH check must coexist with our `40-substitute-app-url.sh` (it writes into the webroot, which uid 101 may not own). Test: `docker build web/` succeeds and `frontend/src/lib/csp.test.js` (upstream) passes with our index.html's inline-script hash.
